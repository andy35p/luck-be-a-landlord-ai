# 实时建议读取链路

已实现 `watch_live_advice.py` 与 `luck_agent/evaluation/live_feed.py`。读取器只读采集日志，在终端输出建议或明确的不可用原因；不点击游戏、不写存档、不显示游戏内悬浮窗。

启动时跳过已有日志，只处理新增完整记录。超过 1 MB 的积压、半条记录、损坏 JSON、日志截断、同时变化的多个会话和缺失/过旧采集时间均撤销建议。只使用最新完整记录，旧观察不会逐条变成“实时建议”。会话、序号和游戏时间的检查继续交给 LiveAdvisor。

新增记录必须携带 captured_unix_seconds，本机墙钟年龄不超过 1.5 秒且不得来自未来；建议在接收后最多保留 2 秒。轮询间隔 100 ms，不能理解为零延迟撤销。系统时间跳变会保守拒绝。调用方应以最新输出为准。

为了静止选牌仍可保持新鲜，准备了 `integrations/collector_v03`：状态变化仍每 250 ms 检查，未变化时约每秒发送一条带新序号和时间戳的状态。插件版本 0.3.0，记录 schema 保持 0.2 并增加时间字段。这会增加日志体积。

0.3 构建产物放在 `logs/collector-v075/build`；现已安装并完成下述实机验证。旧 0.2 不含时间字段，读取器拒绝其新增记录，不能靠文件修改时间伪造新鲜度。

运行方式：

```powershell
.\watch_live_advice.ps1 -Seconds 60
```

相关测试验证启动不回放、过期、心跳恢复、分段写入、坏记录和并发日志拒绝。该链路仍使用受限启发式，不会将未支持的原版符号交给 BC 模型。

发现并绕过运行时目录不一致：Microsoft Store Python/原模型虚拟环境看到 22 个旧日志文件，普通 Python 能看到游戏最新文件。这也解释了此前直接读取最新会话失败、改用 PowerShell 复制后成功的现象。历史 22 文件审计不是本机全部日志审计，不应继续按全量解释。

新增 PowerShell 启动器默认使用本机已有的非 Store Python，并先比较 Windows 与 Python 可见的最新文件；不一致时明确停止。可用 `-PythonPath` 指定其他运行时；该默认路径是本机开发依赖，不是面向玩家的发布安装方案。

实机快照与消费日志位于 `logs/collector-v076/`，摘要为 `reports/live_heartbeat_validation.json`。13 项相关测试通过。下一步接游戏内只读显示；模型训练和默认策略未改变。
