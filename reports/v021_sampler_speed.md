# V0.2.1：不改变决策的重掷估值加速

## 【当前版本与目标】
V0.2.1。只优化重掷估值的计算方式，不改规则、候选概率、抽样次数、策略评分或重掷阈值。默认仍为原启发式；上一轮重掷策略未获得有效提升的结论不变。

## 【现状与发现的问题】
V0.2中重掷策略约9.8局/秒，明显慢于原启发式。对30局做cProfile，808次估值的累计耗时为6.388秒，其中重复候选采样列表约5.874秒；有效稀有度函数被调用约822万次。剖析带有计时开销，不能当作正常运行吞吐量。

## 【原因假设】
同一次估值中的16次采样共享牌组、物品、阶段、候选池和稀有度修正，但旧实现每次逐槽重新扫描并判定。如果预计算有序分组，可减少重复计算，同时保留随机调用次序。

## 【本轮修改】
- `env/offer_sampler.py`：新增独立估值专用的PreparedSymbolOffers，准备候选过滤、有效稀有度分组、频次权重和概率。每次采样复制可用分组，无放回选择，并保留current_offer/offered_rare_slots语义。
- `agents/reroll_agent.py`：保留reference后端，用prepared后端在同一次估值内复用准备结果。每个新状态重新准备，没有跨状态缓存。
- `evaluation/benchmark_reroll.py`：先精确比较完整估值和动作，再交替顺序做多轮计时及结果哈希核验。实时游戏引擎仍为旧代码，未改原文件。

## 【实验设计】
正确性：0–299共300个开发种子，每一步将相同公开状态同时交给新旧策略。实际环境执行一致动作；任一动作或估值字典不一致即失败。
速度：双方预热后交替执行reference/prepared与prepared/reference，各3轮，每轮100局，种子0–99。比较中位耗时，要求结果哈希全部相同。

## 【评价指标与预期结果】
成功门槛在运行前记录为：精确比较零差异，且中位加速比大于1.1。结果不满足则不接受优化，不以策略胜率变化掩盖语义差异。独立验证种子仍未用于本轮开发。

## 【实现与测试】
240项测试全部通过。差分测试含80种随机公开状态组合、每种连续16次采样，以及候选为空、强制跳过、缺少稀有度、稀有槽耗尽等边界；比较候选列表、抽样后的完整RNG状态和环境字段。
300局实际验证：**50,967次决策、7,642次完整估值，零差异**；累计仍为20次重掷，平均通过租金5.6167。仅证明当前测试范围内一致，不代表所有未来规则自动等价。

## 【运行命令】
```powershell
python run_tests.py
python -m luck_agent.evaluation.benchmark_reroll
```
