# V101：库存与结算棋盘分离

只读核查当前游戏 Main.tscn 的 Reels 子资源：shuffle_tiles 从每个 reel.icons 汇总库存池，重分配回 icons，并单独处理场外非空符号；times_displayed 则在 displayed_icons 上递增。证据事实与指纹见 v101_inventory_source_facts.json。由此可确认两套集合用途不同，但不据此宣称所有过渡时刻的库存都已验证完整。

准备 collector_v07 候选，沿用 0.6 计时字段，新增 displayed_board（宽、高、逐行实例编号）。直接读取 displayed_icons，空槽保留 null，不用坐标或 UI 文字推断。原库存采集保持不变。构建 0 警告、0 错误；尚未实机安装，不能把编译成功当成 GDScript 运行证明。

新增 live_board.displayed_ids：当前只接受 5×4 棋盘，验证格数、非空唯一实例身份，以及每格身份都存在于完整采集库存。返回顺序不可变的实例编号元组。库存可以多于 20；本模块不推断计数或收益，也不替代动画/决策稳定检查。

4 项测试通过：场外库存保留、坐标不能补缺失棋盘、缺失/重复/未知实例拒绝、尺寸与缺格拒绝。均为合成契约测试，尚没有 displayed_board 的实机回归夹具。

本轮未修改实际游戏安装、用户存档、旧引擎、训练或建议白名单。生产仍 0.5，最新交付包仍 V097。下一步实机核对显式棋盘与库存映射，并获取非空符号未出场时计数保持的证据；通过前不推广候选版本。
