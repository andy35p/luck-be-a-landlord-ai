# V0.5.6：多进程批量评估

标准评估入口新增 `--workers`，默认 1，保持单进程行为。多进程按连续种子区间分配任务，每个进程独立创建环境和代理，按种子顺序汇总；进程数超过局数时自动限制为局数。子进程异常传回主进程，不输出不完整的成功评估。

Windows 使用 spawn，测试入口新增 main 保护以防子进程递归执行测试。评估 manifest 保存请求/实际进程数和计时范围；并行耗时包含进程池启动、执行与关闭，串行仍保留原有对局循环口径。

## 验证

360 项测试通过，覆盖随机/启发式完整对局、非零起始种子、不能整除的分片、截断、进程数大于局数和异常传递。双进程启发式 1000 局的全部逐局指标与 V0.5.3 保存的单进程记录完全一致，见 v056_checks.json。

当前金鱼环境随机代理双进程完成 10000 局（开发种子 0–9999）：

- 平均通过租金：3.2153；平均旋转：24.1479；平均剩余金币：145.0771。
- 租金 1–4 生存率：100%、83.06%、66.71%、39.54%。
- 通关 0，截断 0。
- 本次墙钟 41.59 秒，约 240.45 局/秒、23530 决策/秒。测试与评估曾并发执行，未进行严格吞吐量对照，不能由此宣称固定多进程加速比。

输出：`logs/reused/random-20260923T152232896723Z`。启发式 1000 局输出：`logs/reused/heuristic-20260923T152152145862Z`，平均通过租金 6.417、183 次通关、零截断。

运行示例：

```powershell
python evaluate.py --agent random --games 10000 --workers 2 --config configs/instance_goldfish_v1.json
```

本轮为基础设施验证，不是新种子冻结验证，也未训练模型。并行入口用于聚合评估；需要逐步轨迹 sink 的采集仍使用原单进程 evaluate。自定义 Python 脚本调用多进程入口时须放在 `if __name__ == '__main__':` 保护下。
