# V0.3.0：已验证候选的行为轨迹

将 V0.2.9 已验证的煤炭评分偏移 -1.2 接入采集入口，策略名称为 heuristic_coal_v029。没有继续调参，也没有训练模型。默认策略与环境保持原样。

## 数据契约与验证

轨迹头增加可选 policy_config，保持 schema_version=1 的转移结构兼容。候选头明确记录 coal_score_adjustment=-1.2；原启发式为 0.0。数据清单包含每个策略的配置、环境、种子范围、来源文件哈希，以及轨迹和 CSV 的文件大小及 SHA256。数据用途标为 development_behavior_data_not_holdout。

使用已消费的开发种子 0–99，各采集 100 局。随机、原启发式和候选共 **27448 步精确重放通过**，无截断。286 项测试通过，包括候选采集不改变结果、策略元数据写入和重放。三组逐局结果还分别与之前的开发日志一致，所有输出文件哈希校验通过，见 `v030_collection_checks.json`。

日志：`logs/coal_diagnosis/20260922T031250024070Z`。包含三份压缩 JSONL、三份逐局 CSV、summary.json 和 manifest.json。轨迹重放验证环境动作结果，不单独证明每一步一定由头部声明的策略产生；本轮另用已保存的同种子评估结果交叉核对。

## 行为与收益

| 指标 | 随机 | 原启发式 | 已验证候选 |
|---|---:|---:|---:|
| 局数 | 100 | 100 | 100 |
| 转移数 | 6757 | 6425 | 14266 |
| 平均通过租金 | 2.15 | 2.05 | 4.75 |
| 平均总奖励 | 32.14 | 20.73 | 250.34 |
| 通关局数 | 0 | 0 | 1 |
| 煤炭选入次数 | 190 | 504 | 0 |
| 煤炭删除次数 | 2 | 48 | 0 |
| 煤炭成熟次数 | 11 | 0 | 0 |
| 跳过符号次数 | 405 | 1 | 551 |
| 正奖励步骤 | 1484 | 1422 | 3049 |
| 零奖励步骤 | 5058 | 4798 | 10743 |
| 负奖励步骤 | 215 | 205 | 474 |

候选零奖励步骤占约 75.3%，保留了全部菜单动作。负奖励包含付租的金币支出，不能直接解释为错误决策。候选活得更久、总决策数更多，因此不同策略的动作原始次数不能直接当作同一状态下的选择概率。

这批候选行为中没有选择煤炭，也没有删除动作；它适合作为受限环境的行为样本，但不是覆盖所有动作的专家数据。随机轨迹提供部分额外动作覆盖，但其质量标签应与候选分开保存。当前仍是原始轨迹，未编码张量、未划分训练/验证集、未启动 BC。

## 复现

```powershell
python run_tests.py
python diagnose_coal.py --games 100 --include-validated
```

不加 --include-validated 时仍只采集原来的两种基线。所有本轮比较是开发数据复现，不作为新的独立策略验证。

下一步优先建立数据读取和按 episode_seed 分组的划分工具，确保同一种子的不同策略轨迹不会落入不同集合；检查动作覆盖、完整局与截断局，再准备模型输入。完整游戏的实例规则迁移尚未完成。
