# 工坊独立接入：候选评分显示路径核查

结论：本轮没有完成工坊独立接入。发现可复用的官方动态计算能力，但当前选牌显示入口缺少连接。此前将所有动态计算均视为需要外部运行时的判断过宽；继续把现有 DLL/Python 打包也不能解决这个缺口。

## 新证据

官方 Value Text 教程允许通过 value_text 的 value 使用 var_math。var_math 支持比较变量，其中 symbols_in_inventory 能按类型或组读取包括本次未出现符号在内的库存数量。这意味着基础库存协同评分不一定需要任意脚本回调、文件导出或外部 Python。

本机 PCK 定向核查结果存于 v137_workshop_candidate_display.json，包含资源哈希。Slot Icon 的提示更新调用动态表达式计算；Card 的候选说明取数据库 description/values，没有 value_text 或 parse_var_math 路径；Pico Label 也未发现该计算调用。这是静态路径证据，不是启动游戏的实测，也不是所有可能接口的不可行性证明。

## 最小可行的原生扩展设计（提案，当前游戏尚不支持）

在普通工坊声明式模组中增加独立的候选评分元数据，按原始符号 ID 匹配，避免替换符号身份、影响成就或覆盖原有计时提示。游戏在候选卡片刷新时，用只读的当前库存、物品和经济快照计算分数，在卡片专用区域展示“建议分”。

运行流程：订阅模组 → 原生加载声明数据 → 当前候选建立 → 快照读取 → 有界算术评分 → 原生卡片显示。整个过程无 DLL、Python、外部进程或模型权重加载。

评分表达式只允许确定性算术和明确的只读计数；禁用随机数、效果执行和字段赋值。重掷、移除、换候选时重新计算；卡片关闭时随卡片撤销。非有限结果、未知表达式和超出支持范围的状态不显示分数。初版只能承载经验证的启发式评分，不能宣称已运行 BC/DQN。

这需要游戏作者提供受支持入口；修改本机 Card 场景不会随普通工坊订阅分发，所以本轮未修改游戏包或加载校验。

## 验收条件

1. 仅安装原版游戏并订阅该模组，能加载评分元数据。
2. 候选保持相同、库存协同符号数量变化时，候选评分按预期变化。
3. 同种子对照经济、规则效果、候选序列及 RNG 保持一致。
4. 重掷/移除/菜单切换不残留旧分数，停用模组后恢复原显示。
5. 不改符号身份、稀有度、基础收益、原提示或其他模组的数据。

本轮完成了路径定位和可复算证据；没有构造静态攻略替代动态助手，没有发布/安装模组，没有外发请求，没有使用训练或测试数据。
