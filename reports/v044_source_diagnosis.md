# V0.4.4：分来源损失与标签一致性诊断

冻结 V0.4.3 两个检查点，训练更新为零。分别对原始教师状态与新增模型自身状态计算指标，没有将两个来源混为一个平均值。当前数据均来自训练分区，结果用于解释拟合行为，不能作为泛化证据。

## 新数据得到拟合，但出现取舍

| 来源与指标 | 原始组模型 | 聚合组模型 |
|---|---:|---:|
| 原始来源 NLL（4638 条决策） | 0.3032 | 0.3262 |
| 标注来源 NLL（5816 条决策） | 0.4366 | 0.2951 |
| 原始来源符号准确率 | 72.93% | 70.66% |
| 标注来源符号准确率 | 65.66% | 71.61% |
| 原始来源：教师选、模型跳过 | 111 | 89 |
| 原始来源：教师跳过、模型选 | 48 | 103 |
| 标注来源：教师选、模型跳过 | 600 | 94 |
| 标注来源：教师跳过、模型选 | 11 | 38 |

聚合组在新增状态上的错误跳过减少 506 次，同时反向选取错误增加。原始状态上的反向错误增加 55 次，整体 NLL 和符号准确率变差。这支持“分布适应伴随原分布退化”的描述，而不是“模型完全没有学到新增标签”。不能把固定训练状态上的改善直接等同于自身后续游戏收益改善。

两组都在删除菜单和物品阶段达到这些数据上的 100% 准确率；这些阶段教师标签单一，主要损失来自符号选择。各阶段、牌组大小与教师标签类型分布保存在 v044_source_audit.json。

## 标签冲突与重复检查

两来源共 10454 条多选决策，对完整有序编码输入（scalars、deck、items、candidates）做哈希。发现 10201 个不同输入、216 个重复输入组，其中 210 个组跨来源；同一完整输入出现不同教师标签的组数为 0。

键不含标签、策略、seed 或 step，因此能检测相同输入被标成不同候选位置的情况。候选顺序包含在键中；本次不合并候选置换、牌组重排或均值池化后的表示，也不声称这些情况下没有歧义。不存在精确输入标签冲突，不等于不存在特征丢失或启发式不足。

新增 audit_aggregation_sources.py 与 tests/test_source_audit.py。316 项测试通过，测试确认身份键忽略标签/来源但保留候选顺序和牌组内容。审计前后检查点文件 SHA256 保持相同。未修改混合比例、模型或默认策略。
